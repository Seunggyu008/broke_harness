# Upgrade an installed harness

1. Resolve the selected workspace and use `node <skill>/scripts/update.mjs --target <workspace> --dry-run` from the current skill bundle. An installed configuration and supported manifest are required. If they are missing, use `init` for a fresh installation or inspect the legacy harness for manual reconciliation.
2. Review the proposed creates, replacements, removals, and conflicts. The manifest establishes which harness files were installed. An unchanged owned file can be replaced or retired, a missing canonical file can be restored, and a locally edited owned file that differs from the new bundle requires reconciliation. Existing application files, owner documentation, active and archived plans, and project configuration are preserved. The `/.tmp/` ignore rule is maintained for local workflow artifacts.
3. For a conflict-free preview, apply with `node <skill>/scripts/update.mjs --target <workspace> --approve <preview.approval>`. If files changed since the preview, review a fresh one. The update uses the current local skill bundle and makes no Git changes.
4. Verify with `node <skill>/scripts/doctor.mjs --target <workspace> --tests`. Report the changed files, remaining conflicts, and verification result. If a plan was already in progress, resolve its baseline and verification evidence before resuming.
